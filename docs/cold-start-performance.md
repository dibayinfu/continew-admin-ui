# 无缓存首次访问排查（2026-10-27）

目标：`https://longan.mozi365.com/#/sanitation/boxMap`。

## 线上证据

前面的依赖瘦身已部署：线上首页使用 `index-DBQo-hcE.js`。本次页面通过 Cloudflare 提供 HTTP/2；抽样 JS/CSS 均有 `Content-Encoding: gzip`，带 hash 的静态资源已有一年的 immutable 缓存。不能将慢加载归因于“没有压缩”或“没有配置浏览器缓存”。

一次浏览器禁用 HTTP 缓存的采样：

| 阶段 | 从导航开始计时 |
| --- | ---: |
| HTML 开始返回 | 0.909 秒 |
| 入口 JS、Vue、基础组件和样式开始下载 | 0.917 秒 |
| 基础组件样式下载完成 | 2.803 秒 |
| 首次内容绘制 | 2.848 秒 |
| 首页页面与依赖开始下载 | 2.853 秒 |
| 已保存布局与依赖开始下载 | 3.856 秒 |
| 该布局最后一批样式完成 | 4.267 秒 |

这显示了“入口 → 首页及布局外壳 → 实际布局”的串行下载。框架脚本等到基础依赖就绪后才发现后续资源；低带宽和高 RTT 会放大这一等待。

该样本仅禁用了 HTTP 缓存，没有清除业务 localStorage；使用了已有的 default 布局，因此不是完全隔离的无痕测速。以上数字也不是用户网络的通用结论。另一组 curl 请求到达不同的 Cloudflare 节点（MAN/DUB），首次静态资源出现 MISS，包含额外回源等待；不应把它们相加当作浏览器总耗时。

另外，首次重定向在约 2.852 秒触发了两次首页 fetch；源头是每次 `beforeEach` 都执行版本检查。这些请求没有必要参与首屏网络竞争。

## 本次修改

- `config/plugins/startup-preload.ts`：构建时根据真实输出生成首页和布局的 modulepreload / 样式 preload 信息。在 HTML 解析阶段开始下载，不等待 Vue 初始化后逐层发现依赖。预加载使用 low 优先级，给入口及其基础样式保留下载优先权。读取已有布局设置；无设置时使用项目默认布局。只选择一个布局，只对首页及其已知重定向生效。其他功能维持原有懒加载。
- `src/router/guard.ts`：版本检查改为导航后的延迟任务，30 秒后执行，1 分钟内复用，单次检查 8 秒超时。首次重定向不会重复下载首页。
- 地图源文件、标记、坐标、筛选、数据接口和 SVG 图标没有修改。

这轮调整改善的是资源发现和请求时序，首屏 JS 体积不会因此显著下降。网络建连、CDN 回源及地图第三方服务耗时仍独立存在。
